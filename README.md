# All Present, None Accounted For

Code repository for the MA thesis *"All Present, None Accounted For: Descriptive Invisibility in Amsterdam's Notarial Archive"* (Cultural Data & AI, University of Amsterdam, 2026).

The thesis examines how multiple independent access layers — finding aids, NER models, naming systems, and authority files — converge in leaving historically ordinary populations undiscoverable in fonds 5075 of the Amsterdam City Archives (Stadsarchief Amsterdam).

## Repository structure

```
├── config.example.py              # Path configuration template
├── ner_split.json                 # Train/dev/test inventory split
├── htr_inventory_notary_mapping.csv  # Inventory-to-notary mapping
├── data_collection/               # Stage 1: data acquisition and alignment
├── ner/                           # Stage 2–4: model training, evaluation, extraction
├── analysis/                      # Stage 5–6: RQ2 population analysis and authority matching
└── relations/                     # Stage 7–8: RQ3 relation extraction, networks, validation
```

## Setup

**1. Clone and install dependencies:**

```bash
git clone https://github.com/tjude2003-spec/thesis-descriptive-invisibility.git
cd thesis-descriptive-invisibility
pip install -r requirements.txt
python -m spacy download nl_core_news_lg
```

**2. Configure data paths:**

```bash
cp config.example.py config.py
```

Edit `config.py` to point `DATA_DIR` at the directory containing your data files (see "Data" below). `config.py` is gitignored.

## Pipeline

### Stage 1 — Data collection and alignment (`data_collection/`)

```
data_collection_pipeline_v2.py    Collect Transkribus index, VeleHanden annotations, SAA finding aids
fetch_htr_corpus_fast.py          Download HTR page texts from Transkribus
merge_caches.py                   Merge Windows and Mac HTR caches
verify_manifest.py                Verify cache completeness, output JSON reports
compute_completeness.py           Compute and plot HTR completeness per inventory
map_inv_to_notary.py              Map inventory numbers to notaries via SAA ranges
```

### Stage 2 — NER model training (`ner/`)

```
create_training_data.py           Generate BIO-tagged training data via distant supervision
clean_training_data.py            Post-process training data (strip artifacts)
train_ner.py                      Convert CoNLL to spaCy format and train adapted model
domain_adaptation_pipeline.py     Feasibility testing for distant supervision approach
```

### Stage 3 — NER evaluation (`ner/`)

```
ner_baseline.py                   Evaluate spaCy off-shelf and adapted models
kaggle_ner_eval_v2.py             Evaluate Flair and BERTje models (runs on Kaggle)
threshold_sensitivity.py          Sensitivity check across matching thresholds
sample_ner_audit.py               Stratified precision audit sample
```

### Stage 4 — Corpus-wide extraction (`ner/`)

```
ner_extract_corpus.py             Run adapted model on full HTR corpus
make_slim_extractions.py          Create offset-free slim CSV for analysis scripts
```

### Stage 5 — RQ2 analysis (`analysis/`)

```
rq2_analysis.py                   Population statistics, frequency distribution
decompose_names_v2.py             Decompose entity strings into name components
rq2_variation_decomposed_v3.py    Orthographic variation analysis with decomposition
cluster_variants.py               Cluster orthographic variants via connected components
recall_by_structure.py            NER recall stratified by name structure type
```

### Stage 6 — External recognition (`analysis/`)

```
external_recognition_decomp.py    SAA decomposed + surface matching, ECARTICO matching
```

### Stage 7 — RQ3 relation and network analysis (`relations/`)

```
build_relations_fast.py           Extract kin/spousal relations from HTR text
rq3_network_stats_v3.py           Network statistics and component classification
rq3_cross_relations_v2_patched.py Cross-notary relation analysis (patched notary attribution)
rq3_case_study_v2.py              Case study sub-networks (Zweerts, Verleij)
rq3_clustering_v2.py              Disambiguation signals for cross-inventory names
```

### Stage 8 — Validation and auditing (`relations/`)

```
check_coverage.py                 Audit indicator coverage for relation extraction
check_recall.py                   Estimate relation recall
check_relation_scope.py           Audit scope of NER file and HTR cache alignment
check_crossinv_types.py           Verify cross-inventory relation type breakdown
check_degree_gap.py               Check degree distribution for threshold justification
recall_probe.py                   Blind relation recall probe with miss attribution
verify_verleij_cluster.py         Verify Verleij case study cluster coherence
make_sample.py                    Generate stratified relation validation sample
```

### Figures (`analysis/` and `relations/`)

```
analysis/plot_frequency_distribution.py    Entity frequency distribution (two-panel)
analysis/plot_name_structures.py           Name structure type distribution
analysis/plot_gender_patronymic.py         Masculine/feminine patronymic waffle chart
analysis/plot_legibility_inversion.py      NER recall vs authority match butterfly chart
relations/plot_relation_types.py           Relation type distribution
relations/plot_case_study_clusters.py      Zweerts and Verleij cluster networks
```

## Notes

- `ner/kaggle_ner_eval_v2.py` is designed to run on Kaggle with GPU access and hardcoded Kaggle paths. It is not intended for local execution.
- The adapted spaCy model is not included. Train it with `ner/train_ner.py` or contact the author.
- `fetch_htr_corpus_fast.py` takes an incredibly long amount of time to collect all HTR transcriptions due to API limitations. 
- All figures are generated at 300 DPI in black and white with Times New Roman font.
